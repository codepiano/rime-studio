# 知键 · Rime 工作台

把“修改配置”和“理解功能”放在同一处的本地 Web 工具。运行时不使用 AI，不调用云端 API，不依赖 CDN。已针对这台 macOS 上的鼠须管 1.1.2、Rime 1.16.0 配置完成第一轮验证。

## 打开与启动

地址：<http://127.0.0.1:4319>。

双击 `启动知键.command` 可启动服务并打开浏览器。也可在本目录执行 `npm install` 和 `npm start`。服务只监听本机环回地址。

默认读取 `~/Library/Rime` 和 `/Library/Input Methods/Squirrel.app/Contents/SharedSupport`。页面里的控件连接的是本机真实配置。改变控件会加入待应用清单，不会立即写文件。预览之后点击保存，才会写入配置。

保存后点击“重新部署”请求鼠须管重载。界面区分请求发送和编译产物更新；编译时间检查不能证明所有应用中的实际打字行为，因此最终效果应在真实输入框里确认。鼠须管 1.1.2 的后台通知可能没有立即送达；请求未能确认时，界面会提示从系统输入法菜单手动重新部署。

## 四个入口

- **调整我的输入**：候选数、排列、字体、配色、Shift 行为、方案菜单按键、方案默认状态、用户词库开关、应用语言规则、半角标点、已安装方案启停及菜单排序。
- **随用随查**：25 张按使用目的组织的操作卡，支持搜索、收藏、跳转到对应设置，以及有限的教学演示。
- **看懂输入方案**：读取真实方案和编译产物，展示按键处理、分段、候选翻译、过滤组件以及拼写规则。只读，不编辑方案定义。
- **源码探索**：浏览固定提交的 Squirrel、librime、plum 和 Wiki 文档。配方、讨论、issue、网志线索与功能卡互相连接。

知识整理的核心是“问题 → 动作 → 效果 → 设置 → 原理”，让识别和探索承担记忆的工作。界面把具体行为命名出来，不让使用者记 YAML 路径。

## 配置与恢复

只写 `default.custom.yaml`、`squirrel.custom.yaml` 和已安装方案的 `.custom.yaml`。使用 YAML 文档节点修改，保留原有注释与不相关字段。方案开关只写 `switches/@N/reset`，不替换整个开关列表。

每次保存都把修改前的完整文本保存在 `.data/backups/<记录ID>/record.json`，并记录修改后哈希。恢复时检查目标文件是否被再次修改；不一致则拒绝覆盖。首次创建的文件可以恢复到不存在。备份包含个人配置，不包含用户词库，且不会被 Git 收录。

服务器用字段白名单、类型检查、固定目标文件、预览版本检查、来源检查和会话令牌保护写操作。未知设置、越界候选数、外部变更、符号链接、无法解析的 YAML 和高级补丁冲突会拒绝写入。请勿将服务通过代理公开到公网。

“恢复继承”指删除对应覆盖。若单项位于带有其他字段的整段覆盖中，删除它不能可靠地恢复原有继承语义，第一版会拒绝此操作。整个 `switches` 列表的自定义覆盖及部分高级 `@last`、`/+` 补丁也不自动拆分。

第一版的配置读取器实现常见根级 `__include` 和常用 patch 路径，不能替代完整 Rime 配置编译器。复杂的嵌套 `__include`、`__patch` 与第三方自定义机制可能无法完全解析；方案流程优先使用已有编译产物，真实合并结果以 Rime 编译产物为准。

## 当前边界

- 外观预览使用示例候选，只模拟排列、字号及主要颜色；系统原生样式、实际字体和窗口定位以鼠须管为准。
- 教学练习使用有限的例子，没有运行 Rime 引擎，也不操作真实用户词库。
- 方案结构只读；未实现新方案安装、词库增删、短语表编辑、模糊音规则编辑、源码构建或插件安装。
- 社区功能卡是探索线索，包含原始出处和验证状态；不把作者声明当作本机验收结果。
- 默认语言和默认字形对应新会话 reset；已记忆的状态还可能受 `save_options` 影响。
- 应用规则中的默认语言与兼容设置分开修改。删除自定义覆盖恢复内置规则，不等于强制中文。

已研究的版本差异与线索：

- 老配方使用 `style/horizontal`，鼠须管新版改用 `style/candidate_list_layout`；已从本机默认配置和 1.1.2 CHANGELOG 核实。

- [Issue #906](https://github.com/rime/squirrel/issues/906) 是 Chromium 非嵌入输入的退格问题；本机默认配置保留 Chrome / Edge 的兼容规则，工具不会覆盖它们。
- [Discussion #2174](https://github.com/orgs/rime/discussions/2174) 展示上屏联想词库，需要 librime-predict；未在本机安装或验证。
- [Discussion #2216](https://github.com/orgs/rime/discussions/2216) 分享混合编码方案；作为扩展线索。
- [仓颉七曜并击](https://rime.im/blog/cangjie-lumiary-chords/)与[分体键盘可视化](https://rime.im/blog/combo-jyutping-sweep-layout/)提供“把规则变成键位与动作”的设计启发。

## 验证

`npm test` 运行 20 项后端测试，覆盖补丁语义、继承、字段验证、注释保留、预览只读、原始字节恢复、首次文件恢复、并存开关、外部变更、符号链接和高级补丁限制。

另在隔离的真实配置副本上调用本机 `rime_deployer --build`，确认引擎 1.16.0 生成：每页 7 个候选、ascii_mode reset=1、simplification reset=1、`/` 输出 `、`；随后恢复原始配置。此验证没有写入真实 `~/Library/Rime`。

浏览器验证使用 Playwright CLI；截图与验收结果参见本目录的 `验收记录.md`。

隔离测试可通过 `RIME_USER_DIR`、`RIME_SHARED_DIR`、`PORT` 覆盖默认路径；设置 `RIME_DISABLE_DEPLOY=1` 禁止测试服务触发真实部署。
